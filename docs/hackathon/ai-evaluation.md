# Menu-scan AI evaluation

Methodology, dataset, and stub-validation results for the Muse menu
extraction path (`src/server/integrations/muse-menu.ts`).

## Status

Live provider inference was NOT evaluated. No live Muse call ran for this
report: no API spend, no latency/accuracy measurement, no one-call/two-call
comparison. Every `liveEvaluation` field in
`tests/fixtures/menu-scans/cases.json` remains `not_run`. The stub results
below validate harness plumbing and response validation only; they say
nothing about model OCR or translation accuracy.

## Methodology

Two layers, kept separate by design:

1. Stub evaluation (ran; results below). A faithful stub extraction is built
   per ground-truth case and driven through the real extractor with a stub
   fetcher: request encoding, bounded body reading, chat envelope and schema
   validation, photograph-reference authorization, retry and timeout paths.
   Ground truth is hand-maintained in `tests/fixtures/menu-scans/cases.json`
   and was never generated by the model under test.
2. Live evaluation (not run). `scripts/eval-menu-scans.ts --live` requires
   BOTH the `--live` flag and `LIVE_MENU_EVAL=1`, refuses to run in CI, and
   blocks cases without raster fixtures instead of calling the provider.
   Raster fixtures do not exist yet (SVG sources are never sent: SVG uploads
   are forbidden), so the live path records `not_run` with a block reason.

## Dataset

- 15 cases in `tests/fixtures/menu-scans/cases.json`, covering Vietnamese,
  Japanese, Chinese, and English menus; multi-page menus; missing prices;
  ambiguous separators and currencies; multiple currencies; illegible photos;
  repeated items across pages; misleading price alignment; unclear portions;
  printed prompt-injection instructions; and malformed provider output.
- 23 expected items across the 15 cases.
- 28 adversarial provider-output checks in
  `tests/fixtures/menu-scans/malformed-responses.json`: truncated envelopes,
  fake JSON payloads (including invented database identities and languages),
  foreign photograph references, unsupported currencies, non-string and
  malformed amounts, executable markup output, misleading currency symbols,
  repeated names, impossible quantities, and printed instruction-override
  attacks. Schema-level attacks are verified offline; model-judgment attacks
  (instruction overrides, ambiguous-symbol interpretation) are recorded as
  live-only and unevaluated.

## Stub-validation results (measured 2026-11-02, stub-fetcher path)

- Cases passed: 15/15.
- Item micro precision: 1.0 (23 matched / 23 extracted).
- Item micro recall: 1.0 (23 matched / 23 expected; 0 missing, 0 invented).
- Exact normalized price accuracy: 1.0 mean over 11 applicable cases
  (18/18 per-item amount sets correct).
- Currency accuracy: 1.0 mean over 12 applicable cases.
- Variant count/association accuracy: 1.0 mean over 14 applicable cases.
- Abstention correctness: 4/4 applicable cases (illegible photo fails
  recoverably; missing/ambiguous/misaligned prices null with review
  uncertainties).
- No invented claims in any extraction; no duplicate names.
- Malformed fixtures: 21/21 evaluated checks rejected (20 rejections plus
  1 repeated-name detection); 7 checks are live-only and unevaluated.
- Sensitivity probes (mutant extractions the scorer must flag): 3/3
  detected — dropped item lowers recall to 0.75, swapped prices lower price
  accuracy to 0.5, invented currency lowers currency accuracy to 0.

These numbers confirm the scorer and the validation pipeline react to the
fixture set; they are not model quality metrics.

## Known errors and limits

- The scorer distributes expected amounts across items evenly in order; all
  15 current cases divide evenly. A case with an uneven item/amount split
  would need an explicit per-item mapping in ground truth.
- "Preserve both source page references" is checked as reference count
  against image count, not asset-ID identity; the extractor itself enforces
  ID authorization separately.
- Currency-symbol ambiguity (`$`, `¥`) and instruction-override resistance
  need live inference; the offline harness records them as unevaluated.
- Per-call token usage and cost estimates are unavailable: the extractor
  contract does not surface provider usage. The live path records null with
  a reason until usage is exposed.

## Reproduction

```sh
# Stub path: free, CI-safe, no provider calls.
bun scripts/eval-menu-scans.ts
bun scripts/eval-menu-scans.ts --out /tmp/menu-eval.json

# Static gates for the new files.
bunx oxfmt --check tests/eval/menu-scan-eval.ts scripts/eval-menu-scans.ts
bunx oxlint tests/eval/menu-scan-eval.ts scripts/eval-menu-scans.ts
bun run check-types

# Live path: gated, never in CI, blocked without raster fixtures.
LIVE_MENU_EVAL=1 bun scripts/eval-menu-scans.ts --live
```
